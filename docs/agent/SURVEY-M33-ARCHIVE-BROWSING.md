## 10. Risks and constraints for the design (facts, with the evidence that makes each a risk)

1. **`FylzV1App.kt` is at its ratchet (2287/2287).** Every hook M3.3 needs is in it: `openEntry` (`:919-930`), the listing effect (`:833-866`), `BrowserState` assembly (`:1131-1157`), the `ActionContext` object (`:994-1122`), the breadcrumb (`:1814-1821`), share/open-with (`:932-940, 1023-1031`). Any line added must be paid for by a line removed (`ui/FylzV1AppSizeTest.kt:18`; `MASTER_PLAN.md:107`).
2. **`Uri` is load-bearing in every model.** `FileEntry.uri`, `FolderLocation.uri`, `FolderTab.treeUri` (`Models.kt:19, 31, 37`); `selectedUris: Set<Uri>` (`BrowserViewModel.kt:67`); `LazyColumn` keys (`FylzV1App.kt:1868, 1874`); `FylzClipboard.entries: List<FileEntry>` → `.uri` on paste (`:686`); `OperationItem.source: Uri`, `TransferWorker` string arrays; `ActionTarget.Entry(FileEntry)`; favourites by Uri; `DocNode.load` queries the Uri (`DocNode.kt:116-119`); every preview and thumbnail opens `entry.uri` through `ContentResolver` (§5); share/`ACTION_VIEW` need a grantable content Uri (§3). A virtual entry without a resolvable content Uri satisfies the *type* but fails at every consumer that queries it.
3. **Session persistence is one JSON string in `SavedStateHandle` and SharedPreferences** (`BrowserViewModel.kt:98-102`). `SavedStateHandle` rides `onSaveInstanceState`, whose Bundle crosses Binder (transaction limit; exact threshold `UNVERIFIED`, commonly cited as ~1 MB per process). Location stacks of names+Uris are small; an archive listing must never be persisted there. Restore filters tabs by `treeUri ∈ persistedUriPermissions` (`:115-118`) — a virtual location's parent tab must still pass that filter (see the `UNVERIFIED` File-backend note in §1).
4. **Binder 1 MB and the 500-row cap.** M3.2 carries ≤ 500 rows (~50 KB) precisely because a full listing overflows the shared 1 MB transaction buffer around ~10 000 entries at ~100 B/entry, and M3.3 must browse ~80 000-entry tarballs; M3.3 owns the full-listing transport (`DESIGN-M32-SEEKABLE-PFD.md` §2.2). `max_listing_entries = 200_000` bounds `:decoders` memory (`DESIGN-M31-PART3:198-201`).
5. **30 s structure budget.** `MASTER_PLAN.md:253` (5 s thumbnails / 30 s structure); `STRUCTURE_TIMEOUT_MILLIS = 30_000` in M3.2 §2.5; a compressed tarball's header pass decompresses the whole stream, so a multi-GB `.tar.xz` **will** time out with "took too long" and M3.2 §4 says M3.3 "needs incremental listing anyway" and revisits the budget. A corrupt archive after 50 000 valid headers returns `CORRUPT` with **no rows** (M3.2 §4 "Partial results").
6. **Nested archives need a real file.** The engine refuses non-`S_ISREG` fds and rewinds to 0 (M3.2 §2.1); `ArchiveSource.resolve` takes a `Uri` (§2.3); an inner archive is an entry with no Uri and no fd, so "extraction to cache" is the only route the M3.2 contract admits. Cache today has no sweeper (§7); `archive-work/` workspaces are per-operation and deleted in `finally`; `maxArchiveBytes` is 2 GiB, so four nesting levels could stage up to 8 GiB worst case (`ArchiveExtractionPolicy.kt:14`). `ArchiveSpacePolicy` and `StatFs(cacheDir)` exist for the space check (`ArchiveSpacePolicy.kt:18-47`; `ArchiveService.kt:417-419`).
7. **Memory in `:decoders`.** The 256 MB address-space target is documented but not enforced (`MASTER_PLAN.md:253`; `SURVEY-M32:20-22`); `read_entry` returns the whole entry body as `Vec<u8>` (`fylz-archive/src/lib.rs:282-290, 222-250`) — a `maxFileBytes`-sized (1 GiB) entry would exhaust the process; part 3's `extract()` streams into caller fds instead (`DESIGN-M31-PART3:61-81`). `:decoders` has no storage and no permissions (`AndroidManifest.xml:84-91`; `DEVICE_CHECKS.md` §14 step 3), so every output fd must be created in the UI process.
8. **Seekable-fd previews.** `PdfRenderer` and `Typeface.Builder` need a seekable descriptor (`PdfPagerPreview.kt:57-58, 75`; `FontFilePreview.kt:38-40`); a pipe cannot serve them. ExoPlayer's requirements over a content Uri: `UNVERIFIED`.
9. **Write actions are gated only by `hasActiveTab`/`HAS_SELECTION`.** `fylz.paste` (`BuiltInActions.kt:138-144`), `new-folder`/`new-file`/`scan-to-pdf` (`:172-189`), `favourite.toggle` (`:325-331`) and all selection-bar write actions (cut, move-to, recycle, rename, tags, compress, rename.batch: `:49-116`) would resolve as enabled inside a read-only archive location; `BrowserState` has no `location.kind` (`BrowserState.kt:19-44`; `DESIGN-MC0:167-169`).
