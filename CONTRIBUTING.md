# Contributing

Thank you for helping build Fylz.

1. Open an issue for large behavior or architecture changes.
2. Keep changes small and separate working capability from placeholders.
3. Add tests for parsers, sorting, conflicts and operation state.
4. Never commit API keys, provider credentials, signing files, private Fonebrew Studio material or user file samples.
5. Run `gradle testDebugUnitTest lintDebug assembleDebug` before opening a pull request.
6. Describe what was tested on a real Android device. CI validates builds and JVM behavior but cannot prove document-provider behavior on every device.

Use clear commit messages and include screenshots or recordings for interaction changes.
